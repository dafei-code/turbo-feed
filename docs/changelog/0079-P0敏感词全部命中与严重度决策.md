# 0079 · P0 敏感词全部命中 + 严重度决策（修复「首词定生死」漏拦）

- **状态**：已完成（tf-gateway 主代码 + 12 个新增单测全绿，编译 + 测试 `BUILD SUCCESS`，2026-10-30）
- **优先级**：P0（功能正确性问题，非性能问题；评审文档「第 1 条」）
- **关联**：0028（内容安全地基）、0026（敏感词单规则拦截）、0031（admin 默认拒绝）

## 为什么做

`ContentSecurityService.check` 走 `SensitiveWordService.match` → `AhoCorasick.firstMatchDetail`，
后者遇**首个命中即 `return`**，于是决策只用「扫描顺序里最早结束的那一个词」的分类定动作。
结果是**首词定生死**：文本先命中低危词（LIMIT/PASS）后命中违禁词（BLOCK）时，旧逻辑取首词 →
放行，**违禁词被漏拦**。这是功能正确性问题，优先级高于所有性能/归一化项。

`AhoCorasick` 类注释（旧 30-32 行）自承「返回全部命中本骨架暂不实现」——印证此处是已知空缺。

## 改动（局限在三层，不动任何调用方）

| 层 | 文件 | 改动 |
| --- | --- | --- |
| 匹配 | `AhoCorasick` | 新增 `allMatches(text)`：单次扫描在每个位置收集 `cur.word` 与沿 fail 链的全部更短命中，按扫描序返回 `List<Match>`（空文本/零命中返回空列表，不返回 null）。保留 `firstMatchDetail`/`firstMatch`/`contains` 兼容旧用途 |
| 动作 | `ModerationAction` | 新增 `severity()`：`BLOCK(3) > REVIEW(2) > LIMIT(1) > PASS(0)`。显式定级，避免依赖 `ordinal()`（枚举声明顺序调整会静默反转裁定） |
| 匹配层 | `SensitiveWordService` | 新增 `matchAll(normalizedText)` 返回 `List<SensitiveWordHit>`；原 `match` 委托 `matchAll().get(0)` 保旧调用方行为 |
| 决策 | `ContentSecurityService.check` | 改用 `matchAll` 收集全部命中；白名单**只减不增**（被豁免词移出决策集）；剩余命中按 `action.severity()` 取最大者裁定；全部豁免则 `exempt`；保留位置回溯与计数 |

### 决策算法（check 内）

```
全部命中 = matchAll(归一化文本)
if 空 → pass
worst = PASS; worstHit = null; anyWhitelisted = false
for hit in 全部命中:
    if 白名单启用 且 isExempt(hit) → anyWhitelisted=true; continue   // 只减不增
    a = actionOf(hit.category)
    if a.severity() > worst.severity(): worst=a; worstHit=hit
if anyWhitelisted: count(WHITELISTED)
if worstHit == null: return exempt(首个被豁免样本词)   // 全豁免
count(worst.name())
return verdict(worst, worstHit 的原文位置)
```

## 影响面核查（改造前已确认安全）

全仓 grep：`SensitiveWordService.match` 仅被 `ContentSecurityService:227` 调用；
`AhoCorasick.firstMatchDetail` 仅被 `SensitiveWordService` 与自身调用。
`MediaUploadService`/`UserService`/`CommentService` 等只调 `requireClean`，决策层内部改造**不波及任何调用方**。
