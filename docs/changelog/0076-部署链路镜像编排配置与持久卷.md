# 0076 · 补部署链路：镜像加固 + 生产编排 + 配置注入 + 行为数据持久卷

- **状态**：已完成（镜像构建未在本机验证，见「验证证据」）
- **优先级**：上线前置项（评审文档 §4 之外的硬缺口：没有任何生产部署产物）
- **关联**：0075（tf-benchmark）、`docs/architecture/behavior-data-pipeline.md`

## 为什么做

项目在代码层面已有 HA / 告警指标 / 压测 / A-B / 归因的能力，但**没有任何生产部署产物**：
一个 `Dockerfile`、一份开发用 compose、没有配置清单、服务容器没有日志卷。结果是
"能力都在，但打不开"——最典型的就是 `behavior-log`：开关一打开，数据写在容器可写层，
`docker compose down` 就永久丢失。

本次补齐四件事：镜像、编排、配置注入、持久卷。

## 改动

### 1. 镜像加固（`Dockerfile`）

| 问题（原） | 改法 | 影响 |
| --- | --- | --- |
| `COPY . .` 在 `mvn package` 之前 | 先只 COPY 各模块 `pom.xml` → `dependency:go-offline` → 再 COPY 源码 | 改一行 Java 不再触发全量依赖下载 |
| `USER root` | 建 `app` 用户（uid 10001），`USER app` | 进程被 RCE 时权限最小化 |
| 无 JVM 参数 | `JDK_JAVA_OPTIONS`：`MaxRAMPercentage=75` / G1 / `ExitOnOutOfMemoryError` | 不再按宿主机内存算堆而被 OOMKilled |
| 装了 curl 但没有 HEALTHCHECK | 镜像级 `HEALTHCHECK`（`start-period=60s`） | 裸 `docker run` 也能被探活 |
| `/app/logs` 不存在 | 预建并 `chown app:app` | 非 root 下 behavior-log 可写；named volume 首挂继承正确属主 |

`JDK_JAVA_OPTIONS` 而非 `JAVA_TOOL_OPTIONS`：前者是 JDK 9+ 原生机制，不需要 `sh -c` 包裹，
进程树更干净（PID 1 直接是 java，信号能正确传递）。

### 2. 生产编排（`deploy/compose/docker-compose.prod.yml`，新增）

**为什么自包含而不是写 override**：Compose 合并多文件时 `ports` / `volumes` 这类列表是**追加**，
要让生产"不暴露中间件端口"必须写 `ports: !reset []`，而该标签要求 Compose ≥ 2.24，
老版本会**静默失效**——端口照样暴露且不报错。自包含文件没有这个陷阱。

| 维度 | 生产编排 | 开发编排 |
| --- | --- | --- |
| 对外端口 | 只有网关 `${TURBOFEED_GATEWAY_HOST_PORT:-8080}` | 全部暴露（便于本机连库） |
| 重启策略 | `unless-stopped` | 无 |
| 资源限制 | 网关/引擎 2G、counter/minio 1G、redis 1G、mysql 2G | 无 |
| 日志轮转 | json-file 50m × 5 | 无（默认无上限，跑久了能写满磁盘） |
| Redis 默认拓扑 | `cluster` | `single` |
| 行为明细卷 | `behavior-logs:/app/logs` | 同（开发也挂，便于本地验证） |

验证结果（`docker compose config --format json`）：`tf-gateway` 1 个对外端口 8080，
其余 6 个服务**全部 0 个对外端口**；命名卷含 `behavior-logs`。

### 3. 配置注入

| 文件 | 内容 |
| --- | --- |
| `deploy/env/.env.example` | 全量变量：分组（必填/拓扑/服务/可选）、生成命令、**正确变量名**、变量名陷阱说明 |
| `deploy/scripts/preflight.sh` | 启动前 5 类校验：必填非空、密钥强度与弱口令、Redis 拓扑自洽、对外地址不能指内网、behavior-log 变量名 |

preflight 打的是 compose `${VAR:?}` 够不到的地方——`${VAR:?}` 只保证"非空"，
管不了"值对不对"：JWT 给 8 个字符 compose 照样放行，直到第一个用户登录才在运行期炸。

其中最值得的一条：**检测 `TURBOFEED_BEHAVIOR_LOG_ENABLED` 这种少了 `FEED` 的写法**。
Spring 对错误的变量名不会报错，只会读默认值 `false`，表现为"开关设了、数据一条没有"。

### 4. 行为数据持久卷

- 生产编排：`tf-feed-engine` 挂 `behavior-logs:/app/logs`，开关默认 `true`（生产该攒数据）。
- 开发编排：同样挂卷，但开关默认 `false`（本地不该静默写文件）。
- 完整存储方案与演进路径见 `docs/architecture/behavior-data-pipeline.md`。

### 5. CI 门禁

新增 3 条检查，避免新文件"写错没人发现"：

- 生产编排可解析（`docker compose -f deploy/compose/docker-compose.prod.yml config`）
- 反证：生产编排缺 `TURBOFEED_INTERNAL_TOKEN` 时必须失败
- `preflight.sh` 语法检查 + 反证：空模板必须被拦下

## 验证证据

- `docker compose config --quiet`：开发编排 ✅ / 生产编排 ✅。
- 生产编排端口与卷：只有网关 8080 对外；`behavior-logs` 卷已声明。
- 反证：`TURBOFEED_INTERNAL_TOKEN` 置空 → 生产编排解析失败（符合预期）。
- `preflight.sh` 四个分支：
  - 全空 → 10 项阻断，退出码 1 ✅
  - 完整正确配置 → 通过（2 条非阻断警告）✅
  - 弱口令 `minioadmin` + 内网媒体地址 + 错误变量名 → 3 项阻断，退出码 1 ✅
  - `bash -n` 语法检查通过 ✅
- **镜像未实际构建**：本机 Docker daemon 未运行。Dockerfile 的正确性目前只有静态审查，
  CI 的 `build` job 不构建镜像（只跑 Maven）。**首次真实构建需要在有 Docker 的机器上验证**，
  特别是分层缓存那一步的 `dependency:go-offline` 行为。

## 风险与未决

- **镜像未构建验证**：这是本次最大的未验证项。若 `dependency:go-offline` 在某模块上失败，
  会走 `|| true` 分支（package 阶段补齐），最坏结果是慢，不会错。
- **`.env` 是明文**：单机 compose 的过渡方案，生产应换 KMS / Vault / K8s Secret。
- **无 TLS**：网关裸 HTTP，生产必须前置反向代理终止 TLS。
- **无备份/恢复演练**：卷有了，但"卷丢了怎么办"没有答案。
- **无灰度与回滚**：`TURBOFEED_IMAGE_TAG` 支持按 sha 打标，但没有编排层的回滚流程。
- **行为数据仍缺采集链路**：卷只解决了「容器重建不丢」，磁盘故障仍会全失；
  P1（定时压缩上传 MinIO）未做，见 `behavior-data-pipeline.md` §5。
