# 0005 - 建立项目技术文档体系（docs/ 与代码同仓）

## 动机

用户明确要求：文档是**项目的技术文档，直接放在代码结构里**。此前 docs/ 下仅有变更记录（changelog）与拆分方案，缺少覆盖"架构 / 模块 / 接口 / 部署"的完整技术文档树，且新接手者无单一入口。

## 改动

新增 8 份技术文档（与既有 changelog 共同构成完整 docs 树）：

```
docs/
├── README.md                    # 文档索引 + 维护约定（本变更引入）
├── architecture/overview.md     # 系统总体架构：3 服务 + 3 库 / 技术栈版本锁定 / 关键决策 / 通信矩阵
├── modules/tf-gateway.md        # 网关：代码结构 / 认证链路 / 上传四薄方法 / 审核 / 事件 / 配置全量键 / 扩展点
├── modules/tf-counter.md        # 计数服务：设计蓝图 + 实现状态清单
├── modules/tf-feed-engine.md    # Feed 引擎：推拉结合蓝图 + 实现状态清单
├── modules/tf-hotspot.md        # 热点 SDK：为何是库不是服务 + 设计方案
├── modules/tf-shared.md         # 契约：Result 结构 / 错误码总表 / 新增规则
├── api/gateway-api.md           # 接口文档：认证约定 / 每接口参数与 curl / 错误码 / 演进
└── ops/deployment.md            # 构建部署 / 环境开关 / 生产前必改清单
```

另：`README.md`（仓库根）增加文档索引段落。

## 文档维护约定（随本变更确立）

1. 代码与文档同步：改类职责 / 接口签名 / 配置键，同一提交内更新对应模块文档；
2. 每变更一份 changelog（编号递增）；
3. 文档只写"为什么"和"契约"，不复述代码；
4. 模块文档与 Maven 模块一一对应。

## 影响面

纯文档，零代码改动，不影响构建与运行。

## 验证

- 文档内容与代码核对编写（接口路径 / 配置键 / 类职责均取自实际源码）；
- 文档间相对链接与目录结构一致。

## 回滚

删除 docs/ 新增文件即可（changelog 0001-0004 保留）。
