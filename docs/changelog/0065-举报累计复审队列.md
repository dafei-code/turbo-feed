# 0065 抖音式「举报累计 → 人工复审」闭环（Tier1）

> 状态：已落地 · 已真实启动验证 · 已端到端验证（tier1_verify.sh 全绿 7/7）
> 关联：抖音分层审核模型（机审初筛 + 账号信用分级 + 举报/申诉闭环）；RBAC（CONTENT_REVIEW / CONTENT_TAKEDOWN）；penalty / appeal 体系

## 一、为什么需要（补的是「复审闭环」缺口）

抖音的内容安全是**分层 + 循环持续审核**：机器初审 → 小流量池 → 人工复审 → 热度复审，
举报/流量激增会触发重审，越火审得越严。turbo-feed 此前只有「初审门 + 投递 + 按需下架」，
缺**复审闭环**——一条已发布内容被多人举报后，没有结构化的二次研判入口，只能靠管理员
从举报列表逐条手翻。

本变更落地三档补强方案中的**第 1 档（举报累计触发人工复审队列）**：

> 当同一内容的**待处理举报数 ≥ 阈值（默认 3）**且内容仍处于 `APPROVED`，
> 自动建一条 `PENDING` 复审任务（`review_task` 单表），归 `REVIEWER` 二次研判
> （违规 → 整帖 `TAKEN_DOWN` + 扣分 + 处罚 / 无违规 → 维持发布）。

第 2 档（热度阈值复审）、第 3 档（流量池分级）未做，留待后续。

## 二、设计

- **触发点**：`MediaReviewService#report` 的普通举报分支（高危类目仍走原有「立即下架停推」）。
  建单前校验三条件，任一不满足即放弃：
  1. 内容仍 `APPROVED`（已下架/申诉中不再建任务）；
  2. 待处理举报数 `countPending(mediaId) ≥ threshold`；
  3. 该 media 无未决复审任务（`existsOpenForMedia` 去重，防重复建单）。
- **阈值外部化**：`MediaProperties.Review.reportReReviewThreshold = 3`，可在 `application.yml`
  调参，不写死在代码里。
- **任务模型**（`ReviewTask` record）：`id / mediaId / authorId / taskType(REPORT_ACCUMULATED)
  / triggerCount(触发时待处理举报数) / status / createdAt / resolvedAt / resolver`。
  `status`：0=待复审 / 1=无违规(维持发布) / 2=确认违规(已下架)。
- **复用与一致性**：
  - 下架复用 `takeDownAndPenalize`（CAS 翻 `APPROVED→TAKEN_DOWN` + 移出时间线 + 扣信用
    + 落处罚），`violationCategory=OTHER` / `severity=MID` / `source=HUMAN_REPORT`，
    CAS 保证并发/重复处置幂等、不双计（与高危举报同力度）。
  - RBAC：`review-task/list` 需 `CONTENT_REVIEW`，`review-task/decide` 需 `CONTENT_TAKEDOWN`
    （`REVIEWER` 与 `ADMIN` 均具备；`resolver` 取当前登录用户）。
  - 处置时 `resolveAllForMedia` 一并清理同 media 的全部待复审任务与待处理举报，避免孤儿任务。
- **存储取舍**：`review_task` 走 **SINGLE 单表落 ds_0 = turbo_feed_1**，仿 `outbox_event`——
  它是管理员视角的**聚合队列**，按 `status` 扫描全貌比按 media 点查更重要；而 `report`
  仍是按 `media_id` 分片的表（单分片点查高效）。

## 三、新增接口（AdminMediaController）

| 方法 | 路径 | 权限 | 说明 |
|------|------|------|------|
| GET  | `/api/admin/media/review-task/list?status=0` | `CONTENT_REVIEW` | 列出某状态复审任务（默认 0=待复审），oldest-first |
| POST | `/api/admin/media/review-task/decide?taskId=&takedown=` | `CONTENT_TAKEDOWN` | REVIEWER 二次研判：`takedown=true` 确认违规下架 / `false` 维持发布 |

`decideReviewTask` 行为：
- `takedown=true`：`takeDownAndPenalize` → `resolveAllForMedia(TAKEDOWN)` → `report.resolve(true)`；
- `takedown=false`：`resolveAllForMedia(RESOLVED)` → `report.resolve(false)`。
