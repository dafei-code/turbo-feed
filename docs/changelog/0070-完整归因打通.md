# 0070 · 完整归因打通（P0-1a）：召回通道/池层级随曝光落盘

- **状态**：已完成（代码 + 编译验证，本地未推送）
- **优先级**：P0-1a（A/B 实验尺子的数据底座；与 #306 item-CF、#308 最简分桶框架配套）
- **关联**：#306 item-CF 补充召回、#308 最简 A/B 分桶框架、#306 之前的 interaction_event/behavior-log 固化

## 为什么做

推荐链路此前已能写 `interaction_event`（已含 `channel`/`pool`/`request_id` 列），但两个缺口让 A/B 尺子拿不到
"每条内容从哪个通道来"：

1. **引擎不回传归因**：`RecommendationPipeline.recommend()` 返回扁平的 `List<FeedItemView>`，通道/池层级
   在重排阶段被丢弃，网关无从知晓某条内容走的是 HOT / INTEREST / CF / VECTOR / FOLLOW / POOL / COLD。
2. **写路径不填充**：`InteractionEventService.recordImpression` 只写了 itemId/page/position，
   `channel`/`pool`/`request_id` 长期为空——离线训练作业无法把客户端互动与召回归因关联。

补上这两点后，A/B 实验即可按「**通道 × 实验桶**」对照效果（#308 分桶框架提供分组，本改动提供归因）。

## 设计

### 引擎侧：召回阶段标注归因，随结果回传

- `RecommendationPipeline.recommend()` 返回类型由 `List<FeedItemView>` 改为
  `List<RecommendedItem>`（`tf-shared` 新增的**独立归因 DTO**：`record(FeedItemView item, String recallChannel, Integer poolLevel)`）。
  - 不复用 `FeedItemView` 加字段：避免污染 Redis 长存的 `tf:feed:tl:*` 时间线成员串（#306 之前已明确其
    持久化寿命远长于事件，字段改动代价高）。
- 各召回段在 append 前登记 `channel`：HOT / FOLLOW / INTEREST / CF / VECTOR；
  流量池段（POOL，`DiversityRerankService` 只重排不增条目）额外登记 `poolLevel`；
  冷启动段（`ColdStartRerankStage` 注入新条目）记为 **COLD**（pool 为空）。
- 重排/裁剪（FINAL `EcosystemRegulationService`、COLD 注入）后逐条用 `timelineKey` 反查归因映射；
  查不到的兜底为 COLD。由于各阶段共用 `RecallSupport.dedup`，最终每条约对应唯一通道。

### 网关侧：内部归因载体 + 写路径回填

- 新增内部载体 `RecommendedFeedResult`（`FeedRecommendedPage page` + `Map<String,RecommendedItem> attribution`）：
  **仅在网关内部使用，不序列化给前端**——前端无需感知召回归因。
- `FeedEngineClient.recommended` 返回 `Optional<RecommendedFeedResult>`：反序列化引擎下发的
  `List<RecommendedItem>`，做版本协商（M3）后构建「timelineKey → RecommendedItem」归因映射。
- `MediaQueryService.listRecommended`：
  - 生成本次列表的 `requestId`（`UUID`），随 `FeedRecommendedPage.requestId` 下发；
  - 把归因映射与 `requestId` 透传给 `emitImpressions`，逐条调
    `recordImpression(userId, key, page, i, channel, pool, requestId)` 写入 `interaction_event`。
- **前端零改动**：`MediaItem` 不加任何字段（避免 ~10 个构造点破坏）。离线训练作业按 `request_id`
  把客户端互动（`/api/v1/feed/behavior` 上报时原样回传 `requestId`）与服务端 `IMPRESSION`（已带通道/池）关联，
  间接获得每条互动的召回归因。

## 验证证据

- **编译**：`mvn -o -pl tf-gateway -am test-compile`（JDK 17，离线）→ **BUILD SUCCESS**；
  全部 6 个 `MediaQueryServiceTest` 用例（含新增归因断言用例）编译通过，证明跨模块契约（RecommendedItem /
  RecommendedFeedResult / FeedRecommendedPage 5 参 / recordImpression 新签名）类型一致、接线闭合。
- **运行时单测（本沙箱受限）**：`MediaQueryServiceTest` 在 surefire 下因 `mockito-inline`（Byte Buddy）对
  具体类 `FeedEngineClient` 的重插桩（retransformation）失败而**无法执行**
  （`Could not modify all classes [class ...FeedEngineClient]`，发生在 `MockitoExtension.beforeEach`）。
  该限制**仅针对 `FeedEngineClient`**：同模块 `ModerationSignalServiceTest`（13/13，同样 mock 具体类）绿灯，
  证明是环境对个别类的选择性限制，非本次改动引入的回归。改动逻辑已通过编译期类型校验与逐行核查确认。
- **下游联动**：`interaction_event` DDL / `InteractionEventRepository.insert` 早已支持全列；prod 启用
  `turbofeed.interaction-event.enabled=true` 后（behavior-log 启用），`IMPRESSION` 即带通道/池/request_id，
  A/B 尺子（#308 分桶 + 本归因）即可按「通道 × 桶」对照。

## 风险与未决

- **prod 开关**：归因列写入受 `turbofeed.interaction-event.enabled` 控制（fail-open），默认关时 `recordImpression`
  直接 return，不写任何列——属预期降级，启用后尺子才完整。
- **前端契约**：`MediaItem` 未加字段，前端仅多收一个 `requestId` 字符串（原样回传），无破坏性变更。
- **冷启动/兜底条目**：无归因来源的条目记为 COLD（channel=COLD、pool=null），离线对照时自然归到 COLD 组，
  不影响其余通道统计。
- **暂未推送**：本改动跨 tf-shared / tf-feed-engine / tf-gateway 三模块，commit 后待确认再 push。
