# 0054 · P2 连刷打散：页内多样性重排

日期：2026-09-28　前置：0053（热点召回 + 分页游标修复）

## 背景

0053 完成后，候选来源已经有了「流量池召回 + 热点召回」两路，但**排序决定谁更重要、
不代表排出来好看**：若某一话题恰好批量过审（一批内容都带同一标签），纯按
`displayScore` 排会让用户连着刷到同一类内容。这既伤体验，也**挤占其它话题的曝光**，
反过来拖累兴趣探索与赛马样本质量。

本次补上 **重排层（重排 = Re-rank）**：抖音式"同类不连刷"。这也补完了 P2 的最后一个可行项。

## 设计

配置 {@code turbofeed.feed.diversity-window}（默认 {@code 3}，{@code 0} = 关闭打散退化为改造前语义）：

> 同一标签的内容，在连续 {@code window} 条之内不重复出现。

实现为**贪心前扫 + 滑动窗口**，而非"给同类内容乘惩罚系数"：

```
逐个输出位干活，在当前窗口允许的前提下，取候选里排名最靠前的那一条。
```

- **为什么不重打分**：目标是「尽量保持打分顺序前提下的最小扰动」。乘系数会整体改写分值分布，
  让排序失去可解释性；贪心只把高分内容推后几名，原序仍是主骨架。
- **为什么用滑动窗口而不是全页去重**：跨页用户本就期望看到重复主题，只需避免
  <b>连着</b>刷到；全页去重会把单页内容多样性压到"每标签至多一条"，过度纠正。
- **打不散时为什么不丢内容**：若窗口内所有候选都撞标签（典型是整页只有一个话题、或可选内容极少），
  按原序取首条。此时<b>不少给内容</b>比"形式上的多样性"更重要——这是重排层的兜底底线。
- **热点槽位钉在最前、不参与打散**：那 10% 是召回策略刻意给的探索位，
  若被重排层搬走，"热门内容靠前"的策略语义就被抹掉了。
- **为什么在整页范围打散而非每池各自打散**：否则相邻两池的交界处（L3 的尾部 → L2 的头部）
  仍会连着刷同一个话题。
- **分页稳定性**：只调整当前页内部相对次序，页成员由 {@code [start, end)} 切片决定不变，
  因此翻页不会重复或漏内容。

## 验证（`target/verify/DiversityVerify.java`，真 Redis 集群，6/6 PASS）

构造 12 条 / 6 个标签、每标签 2 条，且插入顺序刻意让同标签相邻（于是入流时刻倒序天然连刷）：

```
未打散: [tag6, tag6, tag5, tag5, tag4, tag4, tag3, tag3, tag2, tag2, tag1, tag1]   ← 连刷形态
已打散: [tag6, tag5, tag4, tag3, tag6, tag5, tag4, tag3, tag2, tag1, tag2, tag1]   ← 轮转
```

- 关闭打散时确有相邻同类（证明变化确实由打散带来，而非数据偶然）；
- 开启后<b>无相邻同类</b>，且<b>条数不变、内容集合完全一致</b>（重排不丢内容）；
- 退化场景（整页同一标签，无解）仍返回全部内容——宁可连刷也不少给。
