# 0081 · 管理后台新增「敏感词管理」tab（前端页面）

- **状态**：已完成（HTML 标签平衡 + Node 解析 JS 无语法错误，2026-10-30）
- **优先级**：P0 配套（评审「敏感词子系统」收尾项：运营要能点的页面，此前只有 REST API）
- **关联**：0028（内容安全地基）、0079（P0 全部命中 + 严重度决策）、0080（不停机动态添加）

## 为什么做

敏感词管理此前只有后端 REST API（`AdminSensitiveWordController`：`/api/v1/admin/moderation/words`），
没有运营可点的页面——只能用 curl / Postman。管理后台 `turbo-feed-ui/admin.html` 已有
统计看板 + 内容审核队列，但无敏感词 tab。本改动补齐前端入口，与 0080 的「后台异步重建」
配套：页面上加完词立即返回、毫秒级生效。

## 改动（仅前端，不动后端）

| 文件 | 改动 |
| --- | --- |
| `turbo-feed-ui/admin.html` | ① `<style>` 加 `.sw-input`/`.sw-area`/`.sw-tools` 三个表单类；② 侧边栏「核心能力」分组下加「敏感词管理」`nav-item`（`data-target="wordPanel"`），点击平滑滚动到面板；③ 审核队列面板后插入「敏感词管理」`panel`（`id="wordPanel"`）：状态行 + 列表表格 + 新增输入框 + 批量粘贴文本框 + 强制刷新按钮；④ `<script>` 加 `loadWords/addWord/batchAdd/disableWord/enableWord/deleteWord/wordAction/forceReload`，并在进入页面时 `loadWords()` |
| `turbo-feed-ui/sanitize.js` | 未改（复用既有 `esc` / `jsLit` 做 XSS 防护） |

### 接的后端接口（与 0080 一致）

- `GET /api/v1/admin/moderation/words?page=&size=` → 列表（`items`/`dbCount`/`acLoadedSize`）
- `POST /api/v1/admin/moderation/words?word=&category=` → 新增/更新（upsert）
- `POST /api/v1/admin/moderation/words/batch`（`Content-Type: application/json`，body `string[]`）→ 批量导入
- `POST /api/v1/admin/moderation/words/{disable,enable,delete}?id=` → 启停 / 删除
- `POST /api/v1/admin/moderation/words/reload` → 强制刷新 AC

### 安全（沿用既有约定）

- 词条 / 分类等一切后端回包与用户输入经 `esc()` 转义后入 `innerHTML`，`onclick` 里的 id 用 `jsLit()` 包成合法 JS 字面量（与审核队列表格同为 P0-1 XSS 防护写法）。
- 批量导入用 `JSON.stringify(words)` + `Content-Type: application/json`，匹配后端 `@RequestBody`。
- 删除走 `confirm()` 二次确认（硬删除不可恢复）。
