# 0055 · P3 精排模型化（一阶段）：可插拔打分器 + 置信度平滑 + 多目标

日期：2026-09-28　前置：0054（连刷打散）

## 先划边界：这一步是"地基"，不是"上模型"

真正的模型化（双塔召回 / DeepFM 精排）需要**离线训练 + 模型服务**基础设施，
不是一次后端改动能完成的。但走向模型化必须先有三块地基，其中第二块还是**当前的实质性排序缺陷**：

| 地基 | 改造前 | 本次 |
|---|---|---|
| ① 打分可插拔 | 线性算式内联在 `FeedTimelineStore.displayScore`，硬编码 | 抽出 `RankingModel` 接口 + `LinearWeightedRankingModel` 实现 |
| ② 置信度平滑 | `完播率 = completes / impressions` | 贝叶斯平滑（虚拟曝光），修掉小样本霸榜 |
| ③ 多目标 | 只有「完播 + 兴趣」 | 新增「互动率」目标，全部权重外置 |

## 核心修复：小样本霸榜（这是改造前的一个真 bug）

朴素比率把**样本量信息算没了**：

```
A：1 次曝光、1 次完播     → 完播率 100%   ← 一个噪声样本
B：10000 次曝光、9000 完播 → 完播率  90%   ← 久经检验
```

改造前 A 排在 B **前面** —— 刚上线的任意一条新内容，只要有一次完播就能压过万次曝光的
优质内容。这在推荐系统里是典型的 "ratio without confidence" 缺陷，直接伤害内容与分发质量。

**贝叶斯平滑（虚拟曝光）**：

```
smoothed = (successes + priorCount × priorRate) / (trials + priorCount)
```

直觉是"先给每条内容垫 `priorCount` 次虚拟曝光、表现按先验水平"：样本极少时贴近先验
（不轻易给高分），样本足够后被真实数据主导（不埋没优质）。

实证（同一 recency 下）：

| | A（1/1） | B（9000/10000） | 胜者 |
|---|---|---|---|
| 朴素（改造前） | 1.700000540E12 | 1.700000486E12 | **A**（错误） |
| 平滑（改造后） | 1.700000163E12 | 1.700000485E12 | **B**（正确） |

## 设计要点

- **为什么特征是原始计数而不是预先算好的比率**：比率一旦算出就不可逆地丢了样本量，
  平滑就没得做了。这是本次最重要的取舍——`RankingFeatures` 保留 `impressions` 与各项成功数。
- **为什么加"互动率"目标**：完播是弱信号（划过去也算），点赞/评论/分享才是主动表态，
  抖音意义上的"优质"主要看这个。多目标各自独立加权并存，谁更重要由配置决定而非写死。
- **量纲统一**：recency 是 epoch 毫秒（~10¹²），比率是 `[0,1]`，不能直接相加；
  每个比率目标乘 `recencyWindowMillis`（默认 1 小时），语义变成"相当于内容新了一小时"。
- **读路径只做两件事**：取候选 + 组装特征；怎么打分交给模型。将来换双塔 / 接远程推理，
  不必再动这段最热的读代码。
- **恒重排**：原先有个"各加权项全为 0 就跳过排序"的开关，随字段迁出而删除。
  排序对象是页级切片（≤ 页大小），成本可忽略；少一个分支就少一处"权重配错了却以为在排序"的静默分歧。

## 未决（P3 二阶段）

1. **双塔召回**：user/item 向量化 + 向量检索（需离线训练与 ANN 索引）。
2. **精排模型**：DeepFM / 序列模型替代线性加权；本接口已是替换插槽，接远端推理只需换实现类。
3. **特征存储**：当前特征来自 Redis 实时统计 + 画像，缺离线特征（内容 embedding、作者历史表现等）。
4. **粗排分层**：目前候选规模受分桶/页大小限制，规模上去后需"粗排截断 → 精排"两段式。
