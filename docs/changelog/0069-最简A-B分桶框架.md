# 0069 · 最简 A/B 实验分桶框架（P0-1b）

- **状态**：已完成（代码 + 单测，本地未推送）
- **优先级**：P0-1b（推荐/ML 迭代缺尺子的第一块短板）
- **关联**：P0-1a 打开 behavior-log + 固化 interaction_event（本框架提供"分组"能力，下游指标按同公式对齐即可对照）

## 为什么做

此前推荐链路没有任何 A/B 实验手段：要对比"item-CF 召回占比 10% vs 20%"的效果，只能改全局配比发版，
无法做用户级分桶对照，迭代全靠拍脑袋。本框架补齐"分组"这一最小闭环——低代码、零生产风险、fail-open。

## 设计

- **稳定分桶**：`ExperimentBucket.of(userId)` 用 `Math.floorMod(userId.hashCode(), 100)` 把用户稳定映射到
  [0,100) 桶号（每桶约 1% 流量）。下游 `behavior_log` / `interaction_event` 按同一公式对 userId 重新分桶，
  即可对齐实验组/对照组，**无需在链路里透传桶号**。
- **配比覆写**：`ExperimentProperties` 按召回通道名（`HOT`/`INTEREST`/`CF`/`VECTOR`/`FOLLOW`）配置覆写，
  命中分桶的用户用 `ratio` 替换该通道默认配比，其余用户维持默认路径。
- **fail-open**：默认整体关闭（`enabled=false`）；userId 为 null（匿名）、开关关、桶规格非法、覆写 ratio≤0
  都静默回退默认配比，绝不抛异常、绝不影响默认路径。
- **纯函数、可单测**：`ExperimentBucket` 与 `ExperimentProperties.resolveRatio` 均不依赖 Spring 上下文，
  已各自配单测。

## 配置项（prod 启用示例）

```yaml
turbofeed:
  experiment:
    enabled: true
    overrides:
      CF:
        buckets: "0-49"    # 前 50% 用户作为实验组
        ratio: 0.2         # item-CF 召回占比提至 20%（对照组维持默认 10%）
```

> 注意：本框架只负责"分组 + 配比覆写"。效果对照需下游指标（behavior_log / interaction_event）按
> `ExperimentBucket.of(userId)` 对齐分组后做指标对比，本变更不含指标侧改动。
